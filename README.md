Объяснимый подбор вакансий для кандидата. Решение кейса «Сравнительный анализ резюме и вакансий», УРП — отдел кадров МФТИ.

## Основной сценарий

На входе одно резюме и набор вакансий. На выходе — рейтинг всех ролей, рекомендация и разбор каждой пары: требование, подтверждение в резюме, один из четырёх статусов, комментарий. Есть сильные стороны, пробелы, риски, вопросы кандидату и черновик сообщения. Каждый вывод можно сопоставить с фрагментами обоих документов.

В демо уже есть три вакансии и четыре синтетических резюме организатора. Новый браузер начинает с этого набора и получает независимый кабинет. Войдите с любым именем → «Кандидаты» → выберите человека → «Подходящие вакансии». Учебные связи не обозначают реальные отклики.

Дополнительно: чат Qwen3 со ссылками на карточки, голосовой ввод Vosk с редактируемой расшифровкой, озвучивание Piper, история диалогов, выбор нескольких людей на роль («Закадрить»), архив вакансий, обратимое удаление, экспорт HTML/JSON/TXT и исходного резюме. Приложение не отправляет сообщения кандидатам и не принимает решение о найме.

## Запуск в Docker

Нужны Docker Engine с Compose v2 либо Docker Desktop и современный браузер с IndexedDB/Web Locks. Рекомендуются 8 ГБ памяти и 4 CPU для контейнера; на компьютере — 16 ГБ RAM. GPU и ключи облачных AI API не нужны. На VPS проверены Ubuntu 24.04/Linux amd64, 2 vCPU / 8 ГиБ RAM / 20 ГиБ HDD; эта конфигурация работает заметно медленнее рекомендованной.

Linux/macOS:

```sh
chmod +x run.sh
./run.sh
```

Windows с Docker Desktop в режиме Linux containers:

```powershell
.
un.ps1
```

Открыть **http://localhost:8080**. Порт доступен только на127.0.0.1. Windows аппаратно не проверялась; Docker-образ проверен на Linux arm64 и amd64.

Эквивалентный ручной запуск, без изменения исходников:

```sh
docker compose build app
docker compose --profile setup run --rm setup-model
docker compose --profile setup run --rm setup-speech
docker compose up -d --wait app
curl http://localhost:8080/health
```

Первый запуск компилирует llama.cpp и скачивает веса Qwen/Vosk/Piper с проверкой закреплённых SHA-256. GGUF занимает около2,5ГБ, речь — около200МБ с распакованным Vosk. Веса не входят в Git или Docker build context. Если источник речевых весов недоступен с VPS, скачайте их на доступном компьютере тем же скриптом и перенесите `models/speech`: установщик заново проверит SHA. Не отключайте проверку TLS или контрольных сумм.

Остановка и журнал:

```sh
docker compose logs --tail=80 app
docker compose down
```

Для публичного VPS и HTTPS: [deploy/README.md](deploy/README.md), `deploy/compose.yaml`, `deploy/bootstrap.sh`. Микрофон браузера требует localhost или HTTPS.

## Настройки и зависимости

Настройки необязательны. Для локального Compose можно создать `.env` по `.env.example`. Compose передаёт APP_PORT, BROWSER_WORKSPACE, MODEL_THREADS, MODEL_TIMEOUT, PORTAL_LLM_ROWS и LLM_MAX_ROWS. Другие параметры приложения задаются в `environment` сервиса; KADR_DOMAIN относится к публичному развёртыванию.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| APP_PORT | 8080 | Локальный порт |
| BROWSER_WORKSPACE | 1 | IndexedDB + отдельная RAM-сессия;0 — прежний локальный SQLite-volume |
| MODEL_THREADS | 4 | Потоки inference; bootstrap VPS выбирает min(nproc,4) |
| MODEL_TIMEOUT | 180 | Таймаут одного обращения к модели, секунды; VPS240 |
| PORTAL_LLM_ROWS | 2 | Бюджет неоднозначных требований при уточнении кандидата |
| LLM_MAX_ROWS | 6 | Бюджет совместимого API разового анализа |
| MODEL_PATH | /models/Qwen3-4B-Q4_K_M.gguf | Веса внутри контейнера |
| SPEECH_MODEL_DIR | /models/speech | Речевые модели |
| BROWSER_SESSION_LIMIT | 12 | Одновременные временные кабинеты |
| BROWSER_SESSION_TTL | 1800 | Освобождение неактивной RAM-копии, секунды |
| ALLOWED_HOSTS | localhost,127.0.0.1,[::1],testserver | Допустимые HTTP Host; VPS задаёт домен |
| WORKSPACE_PATH | /data/workspace.sqlite3 | Файл только для BROWSER_WORKSPACE=0 |
| KADR_DOMAIN | задаётся при установке VPS | Домен HTTPS-прокси |

Python 3.12, FastAPI/Uvicorn, python-docx/pypdf, llama-cpp-python, Vosk и Piper. Версии прямых зависимостей — в `requirements.txt`, базовый Python-образ и Caddy закреплены digest. Существенные зависимости и лицензии — [THIRD_PARTY.md](THIRD_PARTY.md), [licenses/](licenses/).

Внешних AI/speech API при обработке **нет**. Интернет нужен для первоначального получения пакетов и весов: Docker Hub, PyPI, Hugging Face, alphacephei.com и репозитории ОС. Публичному сайту нужны DNS и выдача/обновление TLS-сертификата. Браузер передаёт документы и голос нашему FastAPI по HTTPS; «локальная модель» означает inference на сервере приложения, а не в браузере. Статика, шрифты и иконки поставляются без CDN.

## Объяснимая оценка

- `full` — полное соответствие; `partial` — частичное; `none` — явное противоречие; `missing` — сведения не указаны.
- Неупоминание навыка не означает его отсутствия. Общий стаж не доказывает профильный; намерение учиться не подменяет опыт. Возраст, пол и гражданство не участвуют в индексе.
- Единые веса: обязательное требование — 3, желательное/задача — 1. Индекс =100×Σ(вес×подтверждённая доля)/Σвесов. Неизвестная доля расширяет верхнюю границу и снижает покрытие. Индекс не является вероятностью успешной работы.
- В составных требованиях самостоятельные инструменты равнодольны, базовое знакомство даёт половину доли инструмента. Для одного навыка с ≥3 деталями половина веса относится к основе, половина к деталям. При ≥90% без противоречий статус полный с небольшим уточнением, но фактический вклад остаётся долевым. Остальное partial даёт 0,5, none/missing —0.
- Рейтинг: индекс по убыванию; при равенстве меньше явных обязательных пробелов, больше покрытие, затем название. Ручной настройки по ФИО/файлам нет. Сводная группа карточки не заменяет статус каждой строки.

Qwen уточняет ограниченное число неоднозначных требований. Проверяются источники, ID и недопустимые повышения. В чате модель определяет намерение и сущности, а фактический ответ собирается из результатов и цитат; ссылки строит сервер. При недоступности модели режим явно обозначается, её применение не имитируется.

## Архитектура и хранение

`DOCX/PDF/TXT/MD → проверка → требования/факты и источники → попарная матрица → рейтинг → рекомендации/экспорт`.

FastAPI обслуживает интерфейс и очередь Qwen в дочернем процессе. Речь обрабатывают Vosk/Piper. Подробный поток, границы компонентов и ошибки — [ARCHITECTURE.md](docs/ARCHITECTURE.md).

Постоянная копия документов, оригиналов, результатов, выбора, архивов, чатов и черновиков хранится в **IndexedDB текущего браузера и origin**. На сервере отдельная SQLite в RAM под случайным токеном; задания и экспорты проверяют владельца. Вкладки одного профиля используют общий кабинет через Web Locks. Имя служит оформлением, не авторизацией сотрудника.

После успешного действия снимок фиксируется до подтверждения UI. При потере RAM-сессии браузер восстанавливает её из снимка; прерванный вопрос можно повторить. Неактивные копии освобождаются. В публичном Compose нет user-data volume, приложение read-only, /tmp — tmpfs, swap контейнера отключён. HTTP access-логи отключены; из ошибок Caddy удалены объекты запросов, включая заголовки с токеном. Аудио обрабатывается в памяти.

Очистка данных сайта стирает кабинет; инкогнито хранит его до закрытия приватных окон. Смена адреса означает другой кабинет. Это демонстрационная изоляция браузеров, не промышленная система аккаунтов или кадровый архив. Прежний локальный volume не загружается на VPS.

## Проверка

```sh
python3 -m pip install -r requirements-dev.txt
python3 -m pytest -q
python3 scripts/check_portal.py --url http://localhost:8080
python3 scripts/check_portal.py --url http://localhost:8080 --with-model
```

Первый тестовый прогон не загружает веса и проверяет логику/границы API. Последняя команда выполняет настоящие модельные запросы в собственном временном кабинете. Верификация: 99 тестов pytest, публичные источники и 4 экспорта, реальное обновление VPS и восстановление снимка с оригиналом/выбором/черновиком, отдельный свежий посетитель с 3 вакансиями и 4 резюме. Подробности — [VALIDATION.md](docs/VALIDATION.md).

На предоставленном наборе frontend первым у Семенова и Петрова, учётная роль у Лилии, куратор у Иванова. Это проверка четырёх учебных резюме, **не универсальная оценка точности**. Два воспроизводимых use cases с входом и ожидаемым результатом — [DEMO.md](docs/DEMO.md).

## Ограничения и развитие

PDF поддерживается при наличии текстового слоя; локальный OCR пока не реализован. Есть лимиты документов/контекста и понятные ошибки, текст не обрезается молча. Фамилии и названия технологий могут распознаваться голосом неверно; расшифровка редактируется до отправки. Живой микрофон на машине защиты ещё нужно проверить.

На текущем VPS с 2 CPU / 8 ГиБ контрольный чат занял 89,9 с, уточнение 2 пунктов — 189,7 с. Это единичные функциональные измерения. Дальнейшие шаги: ускорить inference, провести независимую разметку качества, добавить OCR, затем корпоративные права и кадровые интеграции. Экономия времени и общая точность не заявляются без измерения.
