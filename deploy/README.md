# Кадр на VPS

Публичное демо: https://kadr-51-250-7-79.sslip.io . Текущий проверенный сервер: Ubuntu 24.04, 2 vCPU, 8 ГиБ RAM, 20 ГиБ HDD. Рекомендуются 4 CPU и 8 ГБ RAM; на двух CPU модель работает заметно медленнее. GPU и ключи внешних AI API не нужны.

## Подготовка сервера

Нужны Ubuntu 24.04 LTS, публичный IPv4 и собственный SSH-доступ. В облачной группе безопасности разрешить 22/TCP для SSH, 80/TCP и 443/TCP+UDP для сайта. Закрытый SSH-ключ остаётся на вашем компьютере.

Домен с A-записью должен указывать на IPv4 сервера. Для короткого показа можно использовать имя вида `kadr-203-0-113-10.sslip.io`, если оно разрешается в ваш IP и допускает выдачу сертификата. Для микрофона требуется HTTPS. Хранилище браузера привязано к адресу сайта: смена домена создаёт другой кабинет.

## Установка

Архив собирается из разрешённого списка без SQLite, личных записей, ключей и весов:

```sh
python3 scripts/package_server.py /путь/к/kadr-server.tar.gz
```

Передать архив на собственный VPS по SCP, сверить SHA-256 и распаковать в отдельную папку, например `/opt/kadr`. Затем:

```sh
cd /opt/kadr
sudo bash deploy/bootstrap.sh kadr.example.com
```

При нестабильном SSH запустите длительную сборку независимо от терминала:

```sh
cd /opt/kadr
sudo sh -c 'nohup bash deploy/bootstrap.sh kadr.example.com > /var/log/kadr-bootstrap.log 2>&1 < /dev/null &'
tail -f /var/log/kadr-bootstrap.log
```

Перед повторным запуском проверьте процесс и серверный журнал. Обрыв SSH не доказывает, что сборка остановилась.

Скрипт устанавливает Docker через пакетный менеджер ОС, собирает образ под архитектуру VPS, скачивает закреплённые веса с проверкой SHA-256 и запускает приложение и Caddy. Число потоков — не больше четырёх и не больше числа CPU. Если UFW уже включён, скрипт разрешает HTTP/HTTPS; облачная группа безопасности настраивается отдельно. На сервер попадает код и семь синтетических примеров, без прежнего личного кабинета.

Если сервер не может скачать Vosk с alphacephei.com, запуск остановится с ошибкой. Можно получить те же веса на доступном компьютере командой `python3 scripts/download_speech_models.py`, перенести каталог `models/speech` на VPS и повторить установку: загрузчик проверит контрольные суммы уже имеющихся файлов. Проверку TLS или SHA-256 отключать не нужно.

## Проверка

```sh
curl -f https://kadr.example.com/health
python3 scripts/check_portal.py --url https://kadr.example.com
python3 scripts/check_portal.py --url https://kadr.example.com --with-model
```

В браузере первый посетитель добавляет документ и выбирает кандидата; другой профиль или инкогнито начинает с собственных 3 вакансий и 4 резюме. Обычные вкладки одного профиля разделяют хранилище. Обновите страницу и перезапустите приложение: кабинет восстановится из IndexedDB. Отдельно проверьте экспорт, чат, TTS и живой микрофон через HTTPS на машине показа. API-проверка речи не доказывает работу микрофона.

## Хранение и обслуживание

Документы, оригиналы, оценки, подбор, история и черновики постоянно сохраняются в IndexedDB посетителя. Сервер держит изолированную рабочую копию в RAM. Порт приложения не опубликован, файловая система read-only, временное пространство — tmpfs, swap контейнера отключён. Очистка данных сайта стирает кабинет; инкогнито очищает его после закрытия всех приватных окон. Имя пользователя не является корпоративной авторизацией.

Access-логи приложения и прокси отключены. Из runtime-ошибок Caddy удалены объекты HTTP-запросов и ответные заголовки; причины ошибок сохраняются. Сертификаты находятся в отдельных volumes Caddy.

Команды из `/opt/kadr`:

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml ps
docker compose --env-file deploy/.env -f deploy/compose.yaml logs --tail 100
docker compose --env-file deploy/.env -f deploy/compose.yaml down
```

`down` останавливает контейнеры; для прекращения расходов провайдера нужно отдельно удалить ненужные облачные ресурсы. Остановка/повторный запуск VM с динамическим IP может изменить адрес. Сохраняйте домен и не удаляйте volumes сертификатов при обычном обновлении.
